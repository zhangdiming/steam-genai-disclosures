# Codebook: Authority Allocation in Steam Generative-AI Disclosures

Unit of analysis: the full text of one game's "AI Generated Content Disclosure" section on its
Steam store page. Code only what the text states; do not infer from the game's genre or title.
All binary codes are 1 if the statement is present, 0 otherwise. A disclosure can carry many codes.

## A. Locus of generation (who/what generates, and when)

| Code | Definition | Positive cues | Notes |
|---|---|---|---|
| `pre` | AI-generated or AI-assisted content created **during development** and shipped as fixed content (in-game assets, text, audio, code). | "created during development", "pre-generated", "assets were generated with…", "AI-assisted art in the game" | Default for in-game content when no runtime generation is described. Do not code `pre` if AI was used **only** for store/marketing material. |
| `live_system` | Content generated **while the game runs**, initiated by the game system (e.g., LLM-driven NPC dialogue, dynamically generated quests, procedural images by a generative model). | "in real time", "during gameplay", "dynamically generated by an AI model", "LLM generates responses" | Requires generative AI at runtime. Classic game AI (pathfinding, chess engines, enemy behaviour) is **not** `live_system`; see `non_genai`. |
| `live_player` | Runtime generation **directed by player input** (players type prompts, upload images, request content). | "players can generate…", "based on your text input", "create your own … using AI" | Code both `live_system` and `live_player` if both are described. |
| `marketing` | AI used for store page, capsule/library art, trailers, promotional or community material (trading cards, emoticons, social posts). | "store page", "capsule", "promotional", "trailer", "marketing", "trading cards" | |
| `marketing_only` | `marketing` = 1 and no AI content ships in the game (no `pre`, `live_system`, `live_player`). | "only used for the store page" | Derived; coders still mark it explicitly. |
| `explicit_no_live` | Text explicitly states that the game does **not** generate AI content at runtime / does not connect to AI services during play. | "does not generate content during gameplay", "no AI is used while playing" | |
| `non_genai` | The disclosure describes **only** non-generative or classic AI (chess engines, neural-network recognition, "AI opponents", upscaling without generation is still generative-adjacent: code upscaling as `pre`). | "AI opponents", "enemy AI", "chess engine" | Marks likely misuse of the disclosure field. |

## B. Human authority over AI output (ordinal; code the **highest** level claimed for the in-game content; if only marketing content is described, code for that content)

| Level | Code value | Definition | Positive cues |
|---|---|---|---|
| 0 | `none` | No human role in producing, checking, or changing AI output is stated. "Created with the help/assistance of AI" alone is level 0. | "made with AI", "AI-generated images", "Help in creating images" |
| 1 | `review` | Humans **check, select, curate, approve, or verify** AI output, without stating that they change it. | "reviewed by the developer", "selected", "curated", "checked", "approved" |
| 2 | `edit` | Humans **modify** AI output: edit, refine, retouch, repaint, adjust, rework, mix, integrate after modification. | "edited", "refined", "retouched", "painted over", "adjusted", "reworked", "manually refined" |
| 3 | `human_final` | The final content is stated to be **human-made**, with AI only as reference, inspiration, ideation, brainstorming, or placeholders that were replaced. | "used only as reference", "all final art was hand-drawn", "AI was used for brainstorming", "concepts only" |

Additional binary code in this block:

| Code | Definition | Cues |
|---|---|---|
| `ai_on_human` | AI is applied **to human-originated content** (upscaling original art, polishing or translating human-written text, refining human code, cleaning human recordings). The direction of authority is reversed: humans originate, AI transforms. | "refined with the help of AI", "AI upscaling of our original artwork", "AI-assisted proofreading of our script" |

Adjudication rules added after the dev round (apply in all later coding):
- Placeholders whose replacement is only planned or in progress → `authority` 0 (unless another human role is stated) and `placeholder` 1. Level 3 requires that the shipped content is stated to be human-made.
- Statements that every key asset is hand-crafted / starts and ends in human hands → level 3.
- AI translation counts as `ai_on_human` only when the source text is stated to be human-written or original.
- Concept art, drafts, inspiration references, mock-ups, prototypes → `d_other` 1 (plus the content domain, e.g. `d_visual`).
- "Scripts"/"scripting" → `d_code` unless clearly narrative (dialogue/story script).
- A single named item ("a music track", "the main menu song") does not trigger `scope_minor`; "certain", "selected", "parts of" do. "All other", "every" trigger `scope_extensive`.
- An invitation to give feedback on runtime AI counts as `gr_report`; a general privacy commitment counts as `gr_local`.
- Runtime use of a generative model to evaluate player input (e.g., an LLM judging answers) is runtime generation (`live_player` when the input is the player's), unless the text says the model generates nothing.

Rules: "integrated" alone (no editing verb) → `review`. "Reviewed and edited" → `edit`. A blanket
"all AI content was reviewed and refined" → `edit`. If different assets receive different levels,
code the maximum and set `mixed_oversight` = 1 when the text explicitly says some AI content was
used without modification.

## C. Content domains (multi-label; content that AI produced or assisted)

`d_visual` (art, images, illustrations, sprites, textures, 3D models, UI graphics, animation, video, upscaling) ·
`d_music` · `d_sfx` (sound effects, generic "audio") · `d_voice` (voice acting, TTS, narration, character voices) ·
`d_text` (story, dialogue, narrative, descriptions, in-game writing) · `d_localization` (translation) ·
`d_code` (programming, scripts, shaders) · `d_marketing` (= `marketing`) · `d_other` (ideation, design documents, level design, testing).

Domain codes apply to every AI-produced item the text names, including store and marketing material: a capsule image
or promotional art → `d_visual` 1 (with `marketing` 1); an AI-written store description → `d_text` 1; a trailer voice-over → `d_voice` 1.

## D. Scope and framing

| Code | Definition | Cues |
|---|---|---|
| `scope_minor` | Use is described as limited. | "some", "a few", "minor", "small portion", "limited", "one or two", "only" (restrictive) |
| `scope_extensive` | Use is described as pervasive. | "all", "most", "majority", "entirely", "much of", "fully generated" |
| `placeholder` | AI content is temporary or will be replaced by human work. | "placeholder", "temporary", "will be replaced", "plan to replace" |
| `tools_named` | Names a specific model, product, or vendor. | Midjourney, DALL·E, Stable Diffusion, ChatGPT, GPT-4, Claude, Gemini, Copilot, ElevenLabs, Suno, Udio, Firefly, Leonardo, Meshy, Codex |
| `provenance_claim` | Claims about training data or rights: licensed, ethically sourced, trained on own art, commercially safe, no copyrighted material. | "trained on our own artwork", "licensed", "ethically trained" |
| `small_team` | Justifies AI use by team size or resources. | "solo developer", "small team", "one-person", "limited budget", "indie" |

## E. Runtime guardrails (code only when `live_system` or `live_player` = 1)

| Code | Definition | Cues |
|---|---|---|
| `gr_filter` | Automated output/input filtering or moderation. | "filter", "moderation API", "blocklist", "safety system", "content policy enforcement" |
| `gr_constrained` | Generation constrained in scope: restricted prompts, preset options, system prompts limiting topics, curated templates, closed vocabularies. | "limited to the game's context", "cannot generate", "preset", "restricted" |
| `gr_local` | Local/on-device/offline model or privacy protection (no data sent or stored). | "runs locally", "on-device", "offline", "no data is sent" |
| `gr_human` | Human monitoring, review of generated content, or moderation team. | "our team monitors", "human moderators", "logs are reviewed" |
| `gr_report` | Player reporting or feedback channel for generated content. | "report", "Steam overlay", "contact us if" |
| `gr_optout` | Player control to disable, opt in to, or regenerate AI features. | "can be turned off", "optional", "toggle" |
| `gr_provider` | Relies on the vendor's safety measures or terms. | "OpenAI's usage policies", "provider safety" |
| `gr_none` | Runtime generation described but no guardrail stated. | — |
